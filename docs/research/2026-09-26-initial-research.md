# Initial research (2026-09-26)

Collected 2026-09-26 while writing the requirements. These are facts, not decisions; `docs/requirements.md` cites them as F-numbers.

## Access
- **F1.** Google: a personal-use Cloud project (fewer than 100 users) set to *In production* and left unverified works after a one-time "unverified app" warning. Projects left in *Testing* get refresh tokens that expire after 7 days. Restricted-scope security assessment applies to publicly distributed apps.
- **F2.** Microsoft: since June 2024, app registrations must live in an Entra directory; a personal account gets one free via an Azure signup or the Microsoft 365 Developer Program.
- **F3.** Borrowing another app's client ID is fragile: Microsoft disabled Thunderbird's former app ID in 2024, breaking tools that had reused it.

- **F24.** Google's device-code OAuth flow ("TV and limited-input devices") does not allow Gmail scopes. Headless Google sign-in therefore uses the installed-app loopback flow: the redirect goes to `http://127.0.0.1:<port>`; on a headless server the user either copies the redirected URL back into the tool, or forwards the port over SSH, or signs in on another machine and copies the token. Google blocked the old copy/paste "out-of-band" flow in 2022–2023.
- **F25.** Microsoft's device-code flow works for personal Microsoft accounts: the tool shows a code, the user enters it at microsoft.com/devicelogin on any device.

- **F26.** Microsoft IMAP (`outlook.office.com`) and Graph (`graph.microsoft.com`) are different token audiences, so pimvault needs one access token per resource; obtaining both from one sign-in via the refresh token is expected to work but is unverified.

## Environment
- **F27.** The Claude Code cloud container used for this project ships Go 1.24.7; Go 1.27 (D86) must be installed by a setup step (e.g. a SessionStart hook or the environment's setup script).
- **F27a.** In that container, `go` fetches Go 1.27.0 automatically through the Go module proxy when `go.mod` says `go 1.27.0` (direct downloads from go.dev and dl.google.com are blocked; proxy.golang.org works). Verified 2026-09-26.
- **F27b.** golangci-lint v2.11.3 (onedrive-go's pin) fails on Go 1.27 code ("export data version 4 is greater than maximum supported version 2"); v2.13.2 works. golangci-lint must also be built with the project's Go version: `go install tool@version` otherwise builds with the tool's own minimum (Go 1.26.8 here). Verified 2026-09-26.

## Agent instruction files
- **F28.** Anthropic's Claude Code guidance: keep CLAUDE.md short ("Bloated CLAUDE.md files cause Claude to ignore your actual instructions"); include commands, verification, repo conventions and project-specific decisions; exclude standard language conventions and anything a linter enforces; use hooks for rules that must always run and skills for knowledge needed only sometimes; give Claude a check it can run and have it show evidence.
- **F29.** Anthropic's Opus 5.5 prompting guidance: state outcome, boundaries, verification and completion condition; don't break large tasks into individually supervised steps; drop "think carefully" style instructions (effort controls thinking); fresh-context reviewers should flag only correctness/requirement gaps.

## Change tracking
- **F4.** Gmail `historyId` is typically valid at least a week, but in rare cases only a few hours (Google's `users.history.list` reference; the earlier "~30 days" was a third-party claim); expired → HTTP 404 → full sync. Google People API sync tokens expire 7 days after the full sync. Microsoft Graph delta tokens can expire (410 `syncStateNotFound`) → restart delta from scratch; for Outlook mail they have no fixed lifetime but are evicted from a token cache. Google Calendar sync tokens can expire (410).
- **F5.** Gmail IMAP supports Gmail extensions (`X-GM-MSGID`, `X-GM-THRID`, `X-GM-LABELS`) and CONDSTORE. Exchange/Outlook.com IMAP lacks CONDSTORE/QRESYNC.
- **F6.** Graph change tracking for events is date-window based; it does not track recurring series masters.

## Quotas and limits
- **F7.** Gmail IMAP: 2,500 MB/day download, 500 MB/day upload per account.
- **F8.** Graph (Outlook): 10,000 requests per 10 minutes per app per mailbox; 4 concurrent requests; 150 MB upload per 5 minutes per mailbox.

## Writing into accounts
- **F9.** Gmail `messages.insert` behaves like IMAP APPEND (bypasses most scanning and classification). `messages.import` applies delivery-style classification (`neverMarkSpam` available). Max 150 MB per message via the API.
- **F10.** Graph can create a message from MIME, but it is always created as a draft and the draft flag cannot be changed afterwards.
- **F11.** IMAP APPEND into Outlook.com creates a normal (non-draft) message with the supplied date.
- **F12.** Outlook.com (consumer) message/attachment limit is ~25 MB; Exchange Online allows up to 150 MB.
- **F13.** Graph event creation with attendees always sends invitations; there is no parameter to suppress them.
- **F14.** Google Calendar `events.import` adds a private copy of an event and does not notify attendees. Only `default` event types can be imported; others are converted and lose type-specific properties.
- **F15.** Graph's recurrence model (daily/weekly/monthly/yearly patterns with a range) is narrower than iCalendar RRULE.

## Tasks
- **F21.** Google Tasks API: due dates are date-only (time is dropped); recurrence, reminders and due times exist in the Google Tasks product but are not exposed in the API; subtasks are one level deep and cannot have due dates.
- **F21a.** Google Tasks API has no sync token; incremental reads use `updatedMin` with `showDeleted` (from memory; to confirm against the API reference).
- **F22.** Microsoft Graph To Do API (personal and work accounts): task lists; tasks with checklist items (subtasks), recurrence, reminders, importance, attachments and linked resources; delta queries per task list.
- **F23.** iCalendar `VTODO` is the standard format for tasks; subtasks can be expressed with `RELATED-TO`.

## Identity keys
- **F16.** Graph `iCalUId` differs for each occurrence of a recurring series; Graph `uid` is shared by the series.
- **F17.** `Message-ID` is preserved when the same message is delivered to different providers; your sent copy and the recipient's copy share it.

## Formats and fidelity
- **F18.** Content that is not inside the item and so cannot be preserved by any file format: Gmail confidential-mode messages (the stored copy contains only a link), cloud-storage attachments sent as links (Google Drive, Microsoft "cloud attachments"), Microsoft rights-protected/encrypted mail, live meeting links after an account is gone.
- **F19.** Folder names are localized inconsistently (Outlook.com IMAP; Gmail `[Gmail]/…` follows UI language). Roles can be identified via IMAP SPECIAL-USE and Graph well-known folder names.
- **F20.** Standards available for more metadata if ever needed: JMAP Mail (RFC 8621), JSCalendar (RFC 8984), JSContact (RFC 9553), iCalendar extensions (RFC 7986, RFC 9073), vCard extensions (RFC 9554). Existing on-disk convention for one-item-per-file calendars/contacts: vdir.

## Owner's data profile (aggregate, sampled 2026-09-26)
- Gmail: no user labels in active use (three exist, all left over from earlier migrations); inbox near zero; mail is Inbox / archived / Sent.
- Google Calendar (~5 months sampled): ~92% of events self-organized, ~89% without attendees, ~6% recurring instances, 2 events with meeting links, no colors, attachments or special event types.

## Prior art
- **imapsync** (2.314, Sep 2025): IMAP-to-IMAP migration, restartable without duplicates. Mail only; Microsoft OAuth via external script.
- **Got Your Back (GYB)**: Gmail backup and restore with labels. Gmail only.
- **vdirsyncer** (0.21 upstream, 0.20 in Ubuntu 26.04): CalDAV/CardDAV ↔ vdir sync; Google support needs own OAuth client. No Microsoft support (no CalDAV).
- **DavMail** (7.0, Sep 2026): Exchange/Microsoft 365 as IMAP/CalDAV/CardDAV gateway; Graph mode production-ready only since mid-2026.
- **Open Archiver** (AGPL): compliance archiving; Node/Postgres/Meilisearch/Redis; ingests Workspace/M365/IMAP to `.eml` with dedupe; no restore into mailboxes, no calendars/contacts.
- No existing tool covers mail + calendars + contacts, for both Google and Microsoft, for backup + restore + migrate, headless.

## Libraries
- go-imap v2 is still beta (v2.0.0-beta.8, Feb 2026). The emersion family (go-message, go-webdav, go-ical, go-vcard) comes from the same author. The Microsoft Graph Go SDK is large; Graph is a plain REST/JSON API.

## Setup and client facts (added 2026-09-26)
- **F30.** A Google OAuth app with External user type in "Testing" status gets refresh tokens that expire after 7 days. "In production" without verification shows an unverified-app screen before consent and has a 100-user lifetime cap; personal Gmail accounts count toward it.
- **F31.** Microsoft To Do lists carry `wellknownListName`: `defaultList` (built-in Tasks), `flaggedEmails` (tasks from flagged mail), or `none` (user-created).
- **F32.** Measured: a program that only builds the Gmail service with `google.golang.org/api` v0.299.0 is 22 MB and pulls about 220 non-std packages (gRPC, protobuf, OpenTelemetry); pimvault at the time was 11 MB with 30. Its generated Gmail calls use `gensupport.SendRequest`, which does not retry 429/5xx.
- **F33.** Gmail API from its discovery document: `messages.list` returns at most 500 IDs per page and excludes SPAM and TRASH unless `includeSpamTrash`; `labelIds` filters to messages carrying all given labels; `history.list` takes `startHistoryId` and returns at most 500 records per page.
- **F34.** Graph message delta (per mail folder): supports `$select`; `Prefer: odata.maxpagesize` sets the page size; items that were deleted or moved out of the folder come back as `@removed` with reason `deleted`; an expired state returns 410 Gone or a 40x error with a code such as `syncStateNotFound`, after which the folder is synced again from scratch. With `Prefer: IdType="ImmutableId"` IDs stay the same when an item moves between folders of the same mailbox, and delta links work with either ID format.
- **F35.** Graph has 17 well-known mail folder names (archive, clutter, conflicts, conversationhistory, deleteditems, drafts, inbox, junkemail, localfailures, msgfolderroot, outbox, recoverableitemsdeletions, scheduled, searchfolders, sentitems, serverfailures, syncissues), usable in place of a folder ID whatever the mailbox language.
- **F36.** Google Calendar API (discovery document): calendarList `accessRole` "owner" is a sharing role that several users can have; the calendar's single owner is in `dataOwner`, set only for secondary calendars. `events.list` takes a `syncToken` (410 Gone when it can no longer be used), `showDeleted`, and `iCalUID`, which returns a recurring event with its instances. Events Calendar shows from contacts carry `birthdayProperties.contact`; the owner's own birthday (type "self") has none.
- **F37.** RFC 5545 requires a VTIMEZONE component for each TZID a file uses. Go's time zone database has transitions, not rules; pimvault derives yearly rules from a year's transitions and checks them against the database.
- **F38.** Graph events (v1.0): `/calendars/{id}/events` lists single events and series masters; a master's exceptions come with `$expand=exceptionOccurrences` and its canceled occurrences in `cancelledOccurrences`, only on a GET of the master (F43: not combined with `$select`). Canceled occurrence IDs are `OID.{seriesMasterId}.{date}`, the date in the range's `recurrenceTimeZone`. `iCalUId` differs per occurrence; the series-wide `uid` exists only in the beta API. Times come back in UTC unless a time zone is preferred; `originalStartTimeZone` holds the Windows zone name. Calendars carry `owner`, `canEdit`, `isRemovable` and `isDefaultCalendar`. Unverified: how Outlook.com reports its Birthdays and holiday calendars, and whether all-day times come back as instants or floating midnight.
- **F39.** From MS-OXOCAL (PidLidGlobalObjectId), not yet checked against a live mailbox: Outlook's global object ID, which Graph returns in hex as `iCalUId`, embeds the UID of a meeting created in another system after a "vCal-Uid" marker.
- **F40.** Google's OAuth consent screen (branding, audience, scopes) and OAuth clients for new projects are configured in the Cloud Console; the `gcloud iap oauth-brands/oauth-clients` commands are deprecated and do not work for new projects. Enabling APIs, Secret Manager and service accounts work from gcloud. Secret Manager needs billing enabled; its free tier is 6 active secret versions and 10,000 accesses a month per billing account.
- **F41.** An Entra app for personal Microsoft accounts only has `signInAudience` PersonalMicrosoftAccount, which cannot be changed after creation. Registering one needs a directory to sign in to.
- **F42.** Seen live against a test account (2026-09-26): Gmail `messages.list` with a `fields` mask answers **204 No Content** when the list is empty. `history.list` answers 404 for a start position older than the oldest history record the mailbox still keeps; a mailbox with no activity for months keeps none, so even its current history ID gives 404 until something changes. Positions after the first new record work. Google Calendar sync tokens, series lookup by iCalUID and canceled instances (as EXDATE) behaved as the fakes assume.
- **F43.** Seen live against an Outlook.com test account (2026-09-26): on a GET of a series master, any `$select` (even one naming `exceptionOccurrences`) cuts the expanded exceptions down to `id`; without `$select` they come in full, and the master's default properties include `cancelledOccurrences`. An exception's `originalStart` is a UTC instant (`2026-10-12T06:00:00Z` for a 09:00 Kyiv occurrence). A canceled occurrence's ID ends in its local date (`.2026-10-19`). An all-day event created in Pacific time comes back as `2026-10-20T00:00:00` with `timeZone: UTC` and `originalStartTimeZone: UTC`, so its date is the UTC wall date, not an instant to convert. A new mailbox has only its default calendar; Birthdays and holiday calendars remain unverified.
- **F44.** Seen live against a Gmail test account (2026-09-26): People API photo URLs are listed with a `=s100` suffix, a 100-pixel thumbnail; `=s0` serves the original size (400×400 for a 400×400 upload), and the documented `?sz=` parameter has no effect on these URLs. Default avatars carry `default: true`. Renaming a contact label changes nothing in the connections sync: members are not reported. A deleted contact comes back in a sync with `metadata.deleted: true` and an `updateTime` of 1970-01-01.
- **F45.** Seen live against an Outlook.com test account (2026-09-26): redeeming the Graph refresh token for `https://outlook.office.com/IMAP.AccessAsUser.All` fails with AADSTS70000 ("scopes requested are unauthorized or expired") when sign-in consented only to Graph scopes, though the app registration lists the IMAP permission. Graph `POST /mailFolders/{id}/messages` with a MIME body creates a draft; with a JSON body and `singleValueExtendedProperties` PR_MESSAGE_FLAGS (`Integer 0x0E07`) = 1 set at creation it creates a non-draft message, and PR_MESSAGE_DELIVERY_TIME (`SystemTime 0x0E06`) and PR_CLIENT_SUBMIT_TIME (`SystemTime 0x0039`) set `receivedDateTime` and `sentDateTime`; `internetMessageId` and file attachments are accepted in the same request. Exchange updates `lastModifiedDateTime` of some new events a few minutes after creation.
- **F46.** Seen live against an Outlook.com test account (2026-09-26): `/contactFolders` lists the folders inside the default contacts folder, which is addressable as `/contactFolders/contacts`; deeper folders come from `childFolders`. `/contactFolders/{id}/contacts/delta` returns full contacts, rejects every query option (`$top`, `$select` and others: ErrorInvalidUrlQuery) and ends in a delta link; a later round reports edits and deletions (`@removed`). A birthday comes back as an instant at 11:59 UTC on the day (`1996-11-16T11:59:00Z`). `/contacts/{id}/photo/$value` answers 404 ErrorItemNotFound for a contact without a photo. Of 80 contacts and 10 photos the seeder created (no errors reported), the account kept 75 contacts and 5 photos; unexplained.
- **F47.** Seen live against an Outlook.com test account (2026-10-23): `/todo/lists/{id}/tasks/delta?$expand=checklistItems` returns tasks with their checklists; the delta link it ends with does not show `$expand` in its query, yet later rounds still include checklists. Editing a checklist item reports its task in the next round. Checklist `createdDateTime` has whole seconds and items created together share it; Graph lists them in display order, the same on every call. Due dates come back as midnight with `timeZone: UTC`. Google Tasks documents that tasks completed in Google's own apps are hidden and listed only with `showHidden=true` (tasks.list reference).
- **F48.** Seen live against an Outlook.com test account (2026-10-23), for O31: `POST /me/events` with an attendee and `"isDraft": true` creates the event with the attendee kept and `isDraft` true on read-back; no invitation copy appeared in Sent Items within 2 minutes. The same request without `isDraft` puts the invitation in Sent Items within 20 seconds. Not yet checked: the attendee's inbox (definitive), how Outlook shows such a draft meeting, and what a later update does. A device code request may name Graph scopes and `https://outlook.office.com/IMAP.AccessAsUser.All` together (accepted at the device code step; the sign-in result is pending, O138).
- **F49.** Seen live against an Outlook.com test account (2026-10-23): of contacts created through Graph (`POST /contactFolders/contacts/contacts`, 201 with an ID, readable by ID right after), some later appear neither in listings nor in delta, while others created minutes later stay; 20 of 57 in one run, and earlier 5 of 80 created by the seeder. Not reproducible on demand; cause unknown. A later restore or migrate writes them again, and `verify` shows the gap. Again on 2026-10-24: 26 of 29 contacts a migrate created vanished within minutes; all 26 had no email address and the display name of a contact already in the account, while the 3 that stayed had email addresses. Single test contacts with the same payloads (same name, same fields, same hidden property) created one at a time did not vanish within an hour, so the cause is still unknown.
- **F50.** Seen live (2026-10-24), completing F48: the attendee's Gmail inbox received the invitation for the event created without `isDraft` (filed in Spam) and nothing for the event created with `"isDraft": true`. So `isDraft` suppresses invitations on create.
- **F51.** Seen live (2026-10-24), for O138, adding to F45: a consumer device code request naming Graph scopes and `https://outlook.office.com/IMAP.AccessAsUser.All` together is accepted at the device code step, but the token request fails with AADSTS70011 (invalid_scope). IMAP access therefore needs its own sign-in, separate from the Graph one.
- **F52.** Seen live (2026-10-24): Gmail `messages.insert` replaces a Message-ID that is not a valid RFC 5322 msg-id (seen with `;` and with `[` in the left part, both from Microsoft notification mail) with its own (`<…@mail.gmail.com>`). `rfc822msgid:` search finds neither the original nor such IDs in the account. The Gmail API's metadata headers show encoded display names decoded (for example iso-8859-2 and iso-2022-jp).
- **F53.** Seen live (2026-10-24): `drafts.create` needs a compose scope (403 with `gmail.insert`), but `messages.insert` with the `DRAFT` label under `gmail.insert` creates a draft that `drafts.list` returns.
- **F54.** Seen live (2026-10-24): Calendar `events.import` refuses an event whose organizer is someone else unless the calendar's owner is an attendee (400 `participantIsNeitherOrganizerNorAttendee`). Without an organizer the import succeeds and the owner becomes the organizer, attendees kept.
- **F55.** Seen live (2026-10-24): importing a changed instance with the series' iCalUID and `originalStartTime` attaches it to the imported recurring event (EXDATEs are honored too); imported alone it becomes an orphan instance. Importing again with the same iCalUID updates the existing event, keeping its ID. Contact group names in the People API may repeat and differ only in case; `createContact` takes `memberships` and `clientData`, and `clientData` is readable through `connections`.
- **F56.** Seen live (2026-10-24): Graph `POST /calendars/{id}/events` takes IANA time zone names in `start.timeZone`; a `uid` in the request is ignored (Outlook assigns its own). A series' occurrences are listed with `/events/{id}/instances?startDateTime&endDateTime`; one is changed with PATCH (becoming an exception) or canceled with DELETE. Events carry single-value extended properties like contacts.
- **F57.** Seen live (2026-10-24), for O31: on a meeting series created with `"isDraft": true` and the Gmail test account as attendee, patching one occurrence, deleting another and renaming the series sent nothing to the attendee within 12 minutes; the series stayed `isDraft`. Deleting the draft meeting and the draft series later sent nothing either, while deleting the control meeting (created without `isDraft`) sent the attendee "Canceled: …" at once.
- **F58.** Seen live (2026-10-24): Graph `$filter=internetMessageId eq '…'` finds nothing for long Message-IDs with `;` (Microsoft sharing notifications), even with the exact value Graph returns; valid ones are found. `sentDateTime` can differ from the Date header by a second; `$select=internetMessageHeaders` returns the real Date, From and Message-ID headers (also for Sent Items). A `sentDateTime ge … and sentDateTime le …` filter works.
- **F59.** Seen live (2026-10-25): Graph `POST /mailFolders/{id}/messages` with a MIME body creates a draft, and setting `Integer 0x0E07` (PidTagMessageFlags) afterwards leaves it a draft; a JSON create with `Integer 0x0E07` = 1 among its `singleValueExtendedProperties` creates a non-draft message, but from Graph's fields, not the original MIME. The mailbox import/export API (`/beta/me/mailbox`) answers 404 for a personal account. So Graph cannot import an archived `.eml` unchanged as received mail; IMAP APPEND can. Gmail `messages.insert` takes the system labels SPAM, TRASH, STARRED and IMPORTANT.
- **F60.** For O31 (sources below): macOS Calendar adds an Outlook.com account as an Exchange account and talks to it over EWS, where `CreateItem` with `SendMeetingInvitations="SendToNone"` creates a meeting with its attendees and sends nothing; that is the likely mechanism behind copying events between calendars without new invitations. Unverified live: EWS needs the `EWS.AccessAsUser.All` scope, a sign-in away. - **F62.** Seen live (2026-10-25), for O138 and O31, on the Outlook.com test account with pimvault's Entra app: one authorization code sign-in whose `/authorize` names the Graph scopes, `https://outlook.office.com/IMAP.AccessAsUser.All` and `https://outlook.office.com/EWS.AccessAsUser.All` asks for consent once; the code redeemed with only the Graph scopes gives a Graph token, and its refresh token redeemed with `scope=offline_access https://outlook.office.com/IMAP.AccessAsUser.All` (and EWS) gives an `outlook.office.com` token. The IMAP token request must name its scope: golang.org/x/oauth2 sends none on refresh, and a refresh without a scope gives a working Graph token (checked with Graph `/me`), which keeps the Graph token source as it is. EWS (`https://outlook.office365.com/EWS/Exchange.asmx`) answers every request with that token 403 and an empty body, so O31 option e is not available to pimvault.
- **F63.** Seen live (2026-10-25) on the Gmail test account: a draft created with `drafts.create` (multipart upload of the `.eml`) gets a new Date (the time of the upload) and a new Gmail Message-ID, so it cannot be found again by its original headers. `messages.insert` with `labelIds: ["DRAFT"]` and `internalDateSource=dateHeader` keeps the Date and Message-ID, and the message appears in `drafts.list` as a draft. `messages.import` with the DRAFT label put the message in Spam and not in `drafts.list`. Inserted drafts with DRAFT plus a user label, SENT or INBOX are drafts too, keep those labels, and `q=rfc822msgid:` finds them.
- **F64.** Seen live (2026-10-25): Graph `/me/mailboxSettings/timeZone` answers 403 without the `MailboxSettings.Read` scope; Graph `/me/calendar` has no time zone. Google's calendar list carries each calendar's `timeZone`, and `events.import` refuses a `dateTime` with neither offset nor `timeZone`. `events.import` keeps another organizer when the owner is among the attendees (research note 2026-10-25); with the Outlook test account as an attendee, nothing arrived in its mailbox or calendar within 10 minutes.
- **F65.** Seen live (2026-10-25) on the Outlook.com test account, with `MailboxSettings.Read` consented: `GET /me/mailboxSettings/timeZone` answers 204 with no body, and `GET /me/mailboxSettings` has no `timeZone` property; the only zone it carries is `workingHours.timeZone.name`, a Windows name (`Pacific Standard Time`). Contacts deleted in Outlook stay readable by ID with Deleted Items as their parent folder, and are not listed in any contact folder.
- **F66.** Seen live (2026-10-25), run by the owner from a home connection: Outlook.com IMAP on port 993 with XOAUTH2 answers `NO User is authenticated but not connected.` while the account's "Let devices and apps use IMAP" setting is off, which Microsoft says is the default for personal accounts (https://support.microsoft.com/office/pop-imap-and-smtp-settings-8361e398-8af4-4e97-b147-6c6c4ac95353). With it on, migrating the Gmail test account's 775 messages into the Outlook test account wrote 384 (391 already there), and the next run found all 775 already there.
- **F67.** Seen live (2026-10-25) on the Outlook.com test account: within about five minutes of creation, Outlook.com moves out of the contact folders a new contact identical in its visible fields to an existing one (with or without a pimvault source property; the older contact stays), and a contact with only a display name. A contact differing in one field, or with a name and a note, stays. Outlook on the web counted 137 contacts while Graph's contact folders held 118.
- **F68.** Seen live (2026-10-25), adding to F67: which new contacts Outlook.com moves out is not a plain field comparison. An identical copy in another folder stayed, and so did one with a different category, while one with a different job title was moved out, and earlier one with a different phone stayed. Moved contacts keep their properties, pimvault's source property included (127 of the 154 moved contacts carried one). The undocumented well-known folder `allcontacts` (`GET /me/mailFolders/allcontacts`, the AllContacts search folder) can be listed with `/contactFolders/{id}/contacts` and returns every contact, the moved ones included (275 = 154 moved + 121 in folders), each with its `parentFolderId`. It does not list contacts in Deleted Items.
- **F69.** Seen live (2026-10-25): an end-to-end test run on APFS (case-insensitive) backed up the Outlook test account without errors, but verify found fewer archive files than account items (Inbox 315 of 336, Sent 310 of 341, Calendar 199 of 212, two contact folders one short). A backup of the same account on Linux had all of them; ignoring case, its file names reduce to exactly the APFS run's counts. - **F70.** Seen live (2026-10-26) on the Gmail test account: `messages.insert` (multipart upload, `internalDateSource=dateHeader`) accepted every malformed message tried: no `From`, `From` not an address or empty, no `To`, no or unparseable `Date`, no `Message-ID`, bare LF line endings, a 20,000-character line, an 8-bit Latin-1 header, no headers at all. Gmail keeps them as sent, except that it adds a `Date` (the insert time) when the message has none or an unparseable one, and a `Message-ID` of its own when it has none.
- **F71.** Seen live (2026-10-26): Gmail `labels.create` trims leading and trailing spaces and turns tabs, newlines and repeated spaces into one space, so the label gets another name than the one asked for. It accepts `^`, `[Gmail]`, emoji, `.`, `%`, `\`, `"`, leading and trailing `/`, and 225 characters; it refuses (400 "Invalid label name") 226 characters and the names Inbox, Spam, Drafts, Sent, Archive, Starred, Important, Chats (any case), Sent Mail, All Mail and Muted.
- **F72.** Seen live (2026-10-26) on the Outlook.com test account: Graph `POST /mailFolders` refuses a top-level name equal, ignoring case, to an existing folder, including the non-mail folders Calendar, Contacts and a hidden Files (409 `ErrorFolderExists`). Other names are kept exactly: leading, trailing and repeated spaces, tabs, `/`, `\`, 256 characters.
- **F73.** Seen live (2026-10-26) over IMAP on the Outlook.com test account (from a home connection): `CREATE` answers `NO Folder name is reserved.` for Calendar, Contacts, Files, Tasks, Junk Email and Deleted Items, and `NO Mailbox already exists.` for Notes, a folder IMAP lists but Graph `/mailFolders` (even with `includeHiddenFolders`) does not. Capabilities include UIDPLUS, MOVE and LITERAL+, not APPENDLIMIT. APPEND accepts lines of 10,600 and 30,000 characters (Office 365's 10,500 limit does not apply), bare LF line endings and 8-bit headers.
- **F74.** Seen live (2026-10-26), same setup: APPEND accepts messages up to about 13.8 MB (the limit lies between 13,803,520 and 13,844,480 bytes). From there to at least 35 MB it answers `BAD Command Argument Error. 11`; at 40 MB and above `NO Maximum size of appendable message has been exceeded`. Neither answer carries the `TOOBIG` response code.
- **F75.** Seen live (2026-10-26), same setup: 1,000 small messages appended one after another in 460 seconds (about 7,800 an hour) were all accepted; no throttling. Office 365 documents throttling answers such as "Request is throttled. Suggested Backoff Time: 299961 milliseconds" and closes a session after 10 errors (imapsync's Office 365 FAQ); not seen on Outlook.com.
- **F76.** Seen live (2026-10-26): the Gmail test account has no chats (system label `CHAT` with 0 messages), so how chats are listed and restored is unverified.
- **F77.** From Google's documentation: the Gmail API allows 15,000 quota units per user per minute alongside a per-project limit; exceeding it answers `userRateLimitExceeded`. People API sync tokens expire 7 days after the full sync (reason `EXPIRED_SYNC_TOKEN`). Both are handled: pimvault retries rate limits and does a full listing on an expired token (D50, D69).
- **F78.** Seen live (2026-10-26) on the Gmail test account: `messages.get?format=minimal` returns `sizeEstimate`, which equalled the decoded `format=raw` length for all 40 messages tried (244 bytes to 30 KB). It costs 5 quota units, as a raw download does.
- **F79.** Seen live (2026-10-26) on the Outlook.com test account: the message size Graph lists through the extended property `Integer 0x0E08` (PR_MESSAGE_SIZE, `$expand=singleValueExtendedProperties`) was 1.2 to 15 times the length of the message's MIME (`/$value`) for 40 messages, larger in every case. `mailFolder` has no `sizeInBytes` in v1.0; `HEAD` on `/$value` answers 405; `messages/delta` refuses `$expand` (400). The exact size is known only by downloading.
- **F80.** Seen live (2026-10-26): pimvault's Google project allows 6,000 Gmail quota units per user per minute (`quota_limit_value` 6000 for `totalQueryCostPerMinutePerUser`), not the 15,000 Google documents (F77); over it, Gmail answers 403 with reason `rateLimitExceeded`, which pimvault retries (D69). An end-to-end test run reaches it.
- **F81.** Seen live (2026-10-26) on the Gmail test account, found by the hostile end-to-end test: `labels.create` also limits a name to 255 UTF-8 bytes. Names of "P" followed by 127 `ö` (255 bytes), 84 `€` (253) or 63 `😀` (253) were taken; "P" followed by 128 `ö` (257 bytes), 85 `€` (256) or 64 `😀` (257) answered 500 "Internal error encountered." every time, not 400 "Invalid label name" as over 225 characters (F71). Messages inserted with `messages.insert` were found by an `rfc822msgid:` search seconds later, in both runs of the test.
- **F82.** Measured live (2026-10-26) on the Gmail test account from the agent's development environment, with requests one after another: `migrate` of 1,000 messages of 4.3 KB into the account took 623 s (1.6 a second: a duplicate search and an insert each); running it again, which found all 1,000, took 262 s; a first `backup` of the whole account (1,803 messages, 18 MB, plus 252 events, 132 contacts and 230 tasks) took 933 s. Gmail's quota (F80) would allow about 1,200 message downloads a minute.
- **F83.** Measured live (2026-10-26), Gmail test account: one `format=raw` download at a time ran at 6.5 a second; four at a time burst to 41 a second and 71 of 200 were refused within 5 seconds (403 "Quota exceeded for quota metric 'Total Query Cost' and limit 'Units per minute per user'"), so the per-minute quota is enforced over shorter windows. A first backup with four downloads at once took 810 s against 933 s one at a time, retrying throttled requests for up to a minute each, and two downloads in flight when the access token expired failed with 401. Backup therefore downloads one message at a time.
- **F84.** Seen live (2026-11-01). In the owner's Gmail account, a restore dry run listed a 2022 spam message as missing although it was there; its Message-ID is `<=?utf-8?b?NCgm…JA==?=-1533…@bootique.me>`, an RFC 2047 encoded-word in a valid msg-id. Probed on the Gmail test account with three inserted messages: `rfc822msgid:` finds `<h18?q@…>` and `<h19=e@…>` (a `?` or `=` alone is fine) but never `<=?utf-8?b?aDE3?=-h17@…>`, as written, in quotes or with angle brackets; it finds that one by its decoded form, `rfc822msgid:h17-h17@…`. A Message-ID whose decoded form has a second `@` (`<=?utf-8?b?NCgmXiVeJigjQCQlKg==?=-h20@…>`, decoding to `4(&^%^&(#@$%*-h20@…`) is found by no `rfc822msgid:` query, decoded, quoted, raw or partial. The subject search finds all of them. Whether `format=metadata` gives such a Message-ID as written or decoded was not checked; pimvault compares both forms.
